## 1) الملخّص

| المطلوب | ما نُفِّذ |
|---|---|
| إشعار الرسالة يذهب للطرف الآخر في المحادثة حصراً | `notify_new_message()` تحسم المستلم من `conversations.user_id` و`conversations.admin_id` فقط، بلا أي بديل |
| لا إشعار إذا كان المرسل ليس طرفاً في المحادثة | الحالة (مشاهدة/مراقبة المشرف العام) تُسجَّل في `push_delivery_log` بوسم `SKIPPED` ولا يخرج أي طلب شبكة |
| إشعار المكالمة (`incoming_call` / `call_ended`) للـ `callee_id` حصراً | `notify_call_room()` لا يعرف مستلماً آخر، ويُعيد التحقق من أن طرفي المكالمة هما طرفا المحادثة |
| منع رنين أي حساب آخر — ومنهم السوبر أدمن | بوابة مركزية `push_recipient_allowed()` قبل أي طلب شبكة + فحص `callee_id` من قاعدة البيانات داخل `send-push` + فحص على الجهاز قبل الرنين |
| المشرف العام يرى كل شيء عبر RLS | سياسات `superadmin` معاد إنشاؤها + سياسة جديدة لـ `call_history_hidden` (مراقبة كاملة بلا قيود قراءة) |
| المشرف العام لا يستلم أي تنبيه/صوت لغير محادثاته | وضع صامت كامل: قاعدة البيانات + الدالة + الواجهة (Realtime) |
| إشعار المستخدم الجديد يبقى الإشعار الجماعي الوحيد | `notify_admins_new_profile()` يُعلَن صراحةً كـ `category: admin_broadcast`، ولا يتقاطع مع مساري الرسائل والمكالمات |
| بلا أي تأثير على الجداول أو أنواع البيانات | كل التغييرات **دوال + Triggers + سياسات RLS** فقط (لا عمود واحد جديد) |

## 2) المشكلة قبل الإصلاح

كان توزيع الإشعارات يعتمد على «حساب الطرف الآخر» داخل الدالة، دون حراسة تُلزم المستلم بالحدث نفسه:

1. **إشعار رسالة** كان يُحسب بـ `case when c.user_id = new.sender_id then c.admin_id else c.user_id end`:
   مرسل خارج أطراف المحادثة (وهو مسموح للمشرف العام عبر RLS) يُنتج مستلماً خاطئاً (`user_id` دائماً).
2. **إشعار مكالمة** كان يمرّ بمسار منفصل بلا فحص موحّد على `callee_id` — أي خطأ في الحمولة يعني رنيناً على هاتف غير معني.
3. **إشعار المستخدم الجديد** (`new_user`) إشعار جماعي مشروع، لكن لم يكن هناك ما يمنع نظرياً استخدام نفس المسار الجماعي لإشعار فردي.
4. **الوضع الصامت للمشرف العام** لم يكن موجوداً على الإطلاق:
   * RLS تسمح له بمراقبة **كل** الرسائل، فقناة Realtime العامة في الواجهة كانت تُصدر **صوت إشعار + إشعار نظام + عدّاداً** لكل رسالة في النظام.
   * دعوة مكالمة (Realtime Broadcast) كانت تُقبل بالرنين دون التحقق من أن الجهاز هو `callee_id` فعلاً.

النتيجة العملية: هاتف المشرف العام يتحول إلى جهاز تنبيهات لكل المحادثات والمكالمات في النظام.

## 3) قواعد التوزيع الجديدة (مصدر واحد للحقيقة)

```
                    ┌──────────────────────────────┐
رسالة جديدة  ──────►│ notify_new_message()         │
(بعد INSERT)        │  user_id  مرسل ⇒ admin_id    │──┐
                    │  admin_id مرسل ⇒ user_id     │  │
                    │  غير ذلك       ⇒ لا إشعار   │  │
                    └──────────────────────────────┘  │
                                                      ▼
                     ┌──────────────────────────────────────────────┐
غرفة مكالمة  ───────►│ notify_call_room()                           │
(ringing/مغادرة)     │  المستلم = new.callee_id حصراً               │
                     └──────────────────────────────────────────────┘
                                                      │
تسجيل مستخدم ──────► notify_admins_new_profile()      │
(INSERT profiles)     المستلم = null + التوزيع داخل    │
                      send-push على المشرفين النشطين   │
                                                      ▼
                        ┌───────────────────────────────────────────┐
                        │ push_call_edge(kind, ref, recipient, …)   │
                        │  ⛔ push_recipient_allowed() ⇒ إن لم يطابق │
                        │     الحدث: SKIPPED + بلا أي طلب شبكة       │
                        └───────────────────────────────────────────┘
                                                      ▼
                                   pg_net → send-push → FCM
```

**جدول الحقوق النهائي**

| الحدث | المستلم المسموح | غير المسموح |
|---|---|---|
| `new_message` | الطرف الآخر في نفس صف المحادثة | أي حساب آخر — ومنه السوبر أدمن إن لم يكن `user_id`/`admin_id` |
| `incoming_call` | `call_rooms.callee_id` | المتصل، المشرفون، السوبر أدمن، أي حساب آخر |
| `call_ended` | `call_rooms.callee_id` | نفسه |
| `new_user` | **جماعي**: كل المشرفين النشطين (غير المحظورين) | لا يقبل مستلماً فردياً مطلقاً |
| `probe` / `test` | صاحب الجلسة نفسه | أي حساب آخر |

## 4) تفاصيل التنفيذ

### 4.1 دوال الحراسة (جديدة)

| الدالة | الدور |
|---|---|
| `public.push_recipient_allowed(kind, ref, recipient, body)` | **البوابة المركزية**: تتحقق من مطابقة المستلم للحدث (رسالة/مكالمة/جماعي) وتُستدعى داخل `push_call_edge` قبل أي طلب شبكة |
| `public.push_skip_note(kind, recipient)` | سبب التخطي الموحّد في `push_delivery_log` (ويُصرّح بحالة «مشرف عام ليس طرفاً مباشراً — الوضع الصامت») |
| `public.conversation_direct_recipient(conversation, sender)` | حساب الطرف الآخر حصراً، أو `null` إن لم يكن المرسل طرفاً |
| `public.is_super_admin_user(uid)` | فحص موحّد لصلاحية المشرف العام تُبنى عليه سياسات RLS |

> 🔒 دالتا البوابة والمقابل `revoke` من `anon`/`authenticated`: استخدامها داخلي من Triggers ودوال `SECURITY DEFINER` فقط.

### 4.2 `notify_new_message()` — إشعار الرسائل

1. تُتجاهل بطاقات المكالمات (`message_type = 'call'`) — لها مسارها الخاص.
2. تُقرأ المحادثة (`user_id`, `admin_id`) — وإن كانت غير موجودة: لا إشعار + سطر `SKIPPED`.
3. المستلم = الطرف الآخر في نفس الصف حصراً؛ وإن كان المرسل خارج الأطراف ⇒ لا إشعار لأي جهة.
4. الحمولة تحمل `recipient_id` صريحاً (تتحقق منه دالة `send-push` أيضاً).

### 4.3 `notify_call_room()` — إشعار المكالمات

1. المستلم = `new.callee_id` **فقط**، ويُرفض أي `callee_id` فارغ أو مساوٍ للمتصل.
2. تحقّق مزدوج: طرفا المكالمة (`caller_id`, `callee_id`) هما طرفا المحادثة فعلاً.
3. الحمولة تحمل `callee_id` و`recipient_id` — ولا يوجد أي مسار آخر للرنين (لا بث للمشرفين إطلاقاً).
4. المتصل لا يستلم إشعار رنين (تجربته في الواجهة)، و«انتهت/فائتة» تصل للمستقبِل المعني فقط.

### 4.4 `push_call_edge()` — البوابة المركزية قبل الشبكة

نفس توقيع الدالة السابق (لا يتأثر أي مستدعٍ قائم)، مع إضافة:

```sql
v_allowed := public.push_recipient_allowed(p_kind, p_ref, p_recipient, p_body);
if not v_allowed then
  insert into public.push_delivery_log(kind, ref_id, recipient_id, note) values (…);
  return;   -- لا pg_net، لا FCM، لا صوت
end if;
```

أي خطأ داخل حساب البوابة يُعتبر **رفضاً** (fail-closed) لا موافقة.

### 4.5 `notify_admins_new_profile()` — الإشعار الجماعي الوحيد (مُراجَع)

- يبقى Trigger على `INSERT` في `profiles` فقط، ويُرسل بنوع مستقل `new_user` بمستلم `null`.
- يُضاف وسم `category: admin_broadcast` و`recipients: admins` حتى لا يُفسَّر في الواجهة أو الـ Service Worker كإشعار رسالة/مكالمة.
- لا يحمل أي `room_id` / `message_id` / `conversation_id` (لا تداخل مع المسارين الخاصين).
- الحساب المحظور عند التسجيل لا يُرسل عنه إشعار.
- البوابة المركزية ترفض أي محاولة لإرسال `new_user` إلى مستلم فردي.

### 4.6 `send-push` — نفس القواعد من جهة الدالة

| النوع | التحقق المضاف |
|---|---|
| رسالة | `conversationCounterpart()` تستخرج الطرف الآخر من صف المحادثة؛ المرسل غير الطرف ⇒ `skipped: sender is not a conversation party`؛ وأي تباين مع `recipient_id` ⇒ `recipient mismatch` (409) |
| مكالمة | تُقرأ الغرفة من `call_rooms` (مصدر الحقيقة)؛ إن اختلاف `callee_id` عن الحمولة ⇒ `callee mismatch` (409)، وإن لم توجد الغرفة ⇒ رفض، والإرسال يذهب إلى `callee_id` المقروء من الغرفة حصراً |
| مستخدم جديد | يبقى البث الجماعي الوحيد: `loadAdminIds()` × `loadDeviceTokensForUsers()` |

### 4.7 الواجهة — الوضع الصامت الكامل (`js/notification-scope.js`)

منطق نقي قابل للاختبار في Node، يُطبَّق في ثلاث نقاط:

| النقطة | القاعدة |
|---|---|
| قناة المراقبة العامة (Realtime `messages`) | لا صوت ولا إشعار نظام إلا إذا كان المستخدم **طرفاً مباشراً** في المحادثة (المشرف العام يرى التحديث في القائمة فقط) |
| المحادثة المفتوحة حالياً | لا صوت لرسالة في محادثة المراقبة (السوبر أدمن يفتحها للقراءة فقط) |
| `handleIncomingInvite()` | لا رنين إلا إذا كان الجهاز هو `callee_id` في غرفة `call_rooms` المسجَّلة، ودعوة المكالمة تحمل `calleeId` صريحاً |

الاستثناء الوحيد: المشرف العام **طرف مباشر** (مثلاً `admin_id` في محادثة، أو `callee_id` في مكالمة) — عندها يستلم الإشعار والرنين كأي مستخدم.

### 4.8 RLS — مراقبة كاملة بلا تنبيهات

سياسات المشرف العام (معاد إنشاؤها idempotent، وتبقى مقيّدة بـ `is_super_admin`):

| الجدول | السياسة |
|---|---|
| `conversations` | `conversations full access superadmin` |
| `messages` | `messages full access superadmin` |
| `call_rooms` | `call rooms superadmin` |
| `call_logs` | `call logs superadmin` |
| `push_delivery_log` | `push log superadmin read` |
| `call_history_hidden` | `call history hidden superadmin read` **(جديدة)** |

### 4.9 وضع المراقبة للقراءة فقط (Read-only Observer)

اطّلاع المشرف العام على محادثة **ليس طرفاً فيها** أصبح قراءةً فقط بلا أي أثر على أصحابها:

| الطبقة | القاعدة |
|---|---|
| `mark_conversation_read(conversation_id)` (الخادم) | لا تعديل إلا إذا كان المنفّذ **طرفاً في المحادثة**، وإلا تُعيد `0` بلا أي كتابة |
| `mark_messages_delivered(conversation_id)` (الخادم) | نفس الحراسة — لا ✓✓ لرسائل لا تخصّ المنفّذ |
| `js/app.js` (الواجهة) | `isObserverOfConversation()` تمنع إرسال طلب القراءة/التسليم أصلاً لمحادثة نراقبها |

السبب: بدون هذه الحراسة كان بإمكان المشرف العام (وله حق `UPDATE` كامل عبر RLS) أن يُطفئ
شارات غير مقروء الآخرين ويعرض ✓✓ كاذبة للمرسل لمجرد فتحه المحادثة للمراقبة —
وهذا يتقاطع مباشرةً مع عزل الإشعارات. الاستثناء الوحيد: محادثاته الشخصية (هو طرف فيها)
تعمل بشكل طبيعي تماماً.

ما تتحقق منه `tests/sql-v29-postgres.mjs` (66 فحصاً على محرّك PostgreSQL فعلي):

- تشغيل v2.8 ثم v2.9 فوقها، ثم إعادة تنفيذ v2.9 (idempotent).
- جدول `push_recipient_allowed` الكامل (رسالة/مكالمة/جماعي/معرّفات غير صالحة).
- رسالة من المستخدم ⇒ إشعار واحد لمشرفه؛ رد المشرف ⇒ العكس صحيح.
- المشرف العام يكتب في محادثة ليست له ⇒ **صفر إشعارات وصفر طلبات شبكة**.
- `ringing` ⇒ `incoming_call` للـ `callee_id` فقط، و`missed` ⇒ `call_ended` له فقط.
- محاولة توجيه الرنين للسوبر أدمن في مكالمة ليست له ⇒ مرفوضة (`SKIPPED` مع ذكر الوضع الصامت).
- المشرف العام كطرف مباشر (`callee_id`) ⇒ يستلم رنين مكالمته هو (الاستثناء الوحيد).
- تسجيل مستخدم جديد ⇒ إشعار جماعي واحد بوسم `admin_broadcast` وبلا أي معرّف مكالمة.
- **ثبات القاعدة**: كل صف أُرسل فعلاً في الاختبار يعاد التحقق منه بالبوابة ⇒ صفر انتهاكات.
- **القراءة فقط**: محاولة المشرف العام (ليس طرفاً) لقراءة/تسليم محادثة الآخرين ⇒ `0` وبلا أي تغيير
  في حالة الرسائل، بينما الطرف المباشر يعمل كالمعتاد، والمشرف العام في محادثته الشخصية طبيعي.
- الهجرة تعمل أيضاً على قاعدة باقية ناقصة (بلا v2.8) بتدهور آمن بلا أخطاء.
- وجود سياسات RLS الست وأنها كلها مقيّدة بـ `is_super_admin`.
- مؤشرات `push_diagnostics()` الجديدة (`isolation_version`, `isolation_gate`, `super_admin_silenced`, `skipped_total`).

وما تتحقق منه `tests/notification-isolation.mjs`:
اختبارات وحدة لمنطق الواجهة (17 حالة) + تطابق `schema.sql §17` حرفياً مع ملف الهجرة + أن آخر تعريف فعّال للدوال في `schema.sql` هو المشدّد + أن `new_user` هو الإشعار الجماعي الوحيد + وجود الفحوص في `send-push` و`app.js` و`calls.js`.

## 8) التشخيص والاستعلامات الجاهزة

```sql
-- ① ما أُرسل فعلاً (بلا حالات تخطي) خلال آخر يوم
select kind, count(*) from public.push_delivery_log
where note is null and created_at > now() - interval '1 day'
group by kind order by kind;

-- ② أسباب التخطي (كل "لماذا لم يصل إشعار؟" هنا)
select kind, note, count(*) from public.push_delivery_log
where note like 'SKIPPED%' group by kind, note order by count(*) desc;

-- ③ كم إشعاراً أُكتم عن المشرف العام لأنه ليس طرفاً مباشراً
select count(*) from public.push_delivery_log where note like '%مشرف عام%';

-- ④ مؤشرات العزل من الدالة نفسها
select public.push_diagnostics() -> 'recipient_isolation';
```

## 9) سلوك متوقّع بعد التحديث (حالات حدّية)

| الحالة | النتيجة |
|---|---|
| مستخدم يرسل لمشرفه | إشعار/رنين طبيعي (لم يتغير شيء لمن هو طرف) |

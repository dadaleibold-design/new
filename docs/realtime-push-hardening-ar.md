# إصلاح حلقة Realtime وإشعارات الخلفية — تقرير الهندسة

> التاريخ: 2026-10-12 — الفرع: `arena/b016922b-new`
> يشرح الأسباب الجذرية التي تم التحقق منها بالكود والاختبار، والتعديلات، وخطوات النشر، وما لم يُغيَّر عمداً.

---

## 1) الخلاصة

| المشكلة | السبب الجذري (مُتحقَّق منه) | الإصلاح |
|---|---|---|
| تكرار CHANNEL_ERROR / CLOSED | (أ) `resubscribeRealtime` يهدم **كل** القنوات ويبنيها عند كل حدث (عودة للمقدمة، focus، pageshow، online، نبضة اليقظة) حتى لو كانت سليمة. (ب) قناة يرفضها الخادم تُعاد محاولتها ضمن حدّها، ثم يُعيد المراقب (watchdog) بناءها كل 30 ثانية بعدّاد جديد. (ج) إزالة القناة القديمة تُطلق `CLOSED` فتُضاعف جدولة إعادة المحاولة. | حارس الإلغاء، ونمط Singleton لكل topic، وإعادة بناء القنوات الميتة فقط، وتراجع أُسّي لعمليات الإحياء، وعدم إعادة بناء القنوات المرفوضة نهائياً إلا عبر المراقب |
| قنوات مكررة بنفس الـ topic | `supabase.channel()` لا يمنع التكرار، والكود لم يكن يُغلق القديمة | `createResilientChannel` يُغلق النسخة السابقة ويمنع البناء قبل اكتمال الإزالة |
| قنوات لا تُغلق عند تسجيل الخروج | `SIGNED_OUT` كان يوقف المراقب فقط | `teardownAllRealtime()` |
| `presence sync` يحمّل جهات الاتصال بلا حدّ | كل حدث حضور ⇒ `loadContacts()` | دمج الأحداث بمؤقت 800ms |
| الإشعار لا يُفتح عند النقر | مستمع Firebase SDK يستدعي `stopImmediatePropagation()` عند غياب الرابط، فيبتلع النقرة قبل معالجنا | معالج النقر بمرحلة الالتقاط (`capture`) + إيقاف الانتشار |
| رسالة ثانية في نفس المحادثة لا تظهر | منع التكرار بالـ `tag` وحده: إشعار سابق بنفس الـ tag يُسقط الجديد | منع التكرار بهوية الحدث (`messageId` / `roomId`) |
| بيانات النقرة تفقد المحادثة | الـ SDK يلفّ الحمولة داخل `data.FCM_MSG` ولم يكن الكود يفكّها عند النقر | `normalizePayload` يفكّ `FCM_MSG` |
| مكالمة فائتة تستبدل إشعار المحادثة | `call_ended` كان يستخدم `conversation-*` | `tag` منفصل `missed-<room>` |
| إشعار "إنهاء المكالمة" لا يُعرض في الخلفية | لا يُعرض إشعار لكل دفعة (شرط userVisibleOnly) | استبدال الرنين بإشعار صامت ثم إغلاقه |
| الاشتراك بجدول غير منشور/بلا هوية كاملة | `message_reactions` بلا `REPLICA IDENTITY FULL` ⇒ حذف التفاعل لا يصل؛ `conversations` غير مضاف للنشر في بعض النشرات | ترحيل SQL جديد (idempotent) |

## 2) التعديلات (الملفات)

### `js/realtime.js` (أُعيدت كتابته)
- **Singleton**: `managedChannels` (topic → handle). إنشاء قناة بنفس الـ topic يُغلق السابقة.
- **حارس الإلغاء**: كل استدعاء `subscribe` يتحقق `ch === channel` و`gen === generation`. أي حدث من قناة أُزيلت/استُبدلت يُتجاهل. هذا يكسر تضاعف الجدولة.
- **انتظار الإزالة**: `pendingRemovals` — لا تُنشأ قناة بنفس الاسم قبل اكتمال إزالة القديمة.
- **`ensureHealthy()`**: يعيد البناء فقط إن كانت القناة ميتة. **`rebuild({force})`**: صريح.
- **`failed`**: بعد `maxRetries` تتوقف المحاولات التلقائية (لا حلقة لا نهائية على خطأ دائم).
- **المراقب**: تراجع أُسّي لعمليات الإحياء (`reviveCooldownMs × 2^n` حتى 5 دقائق) يُصفَّر عند عودة كل شيء سليماً.

### `js/app.js`
- `resubscribeRealtime(reason)`: يعيد بناء **القنوات الميتة فقط**. القنوات المرفوضة نهائياً (`failed`) لا يعيد بناءها إلا المراقب (`watchdog*`) أو الإجراء اليدوي.
- `subscribeToConversation`: idempotent لكل القنوات الثلاث (الرسائل/الكتابة/التفاعلات)، ويعيد البناء فقط عند موت إحداها.
- `closeChatView()`: يغلق قنوات المحادثة (مغادرة الصفحة).
- `teardownAllRealtime()`: عند `SIGNED_OUT`.
- `subscribeGlobalPresence` / `subscribeInboxUpdates` / `subscribeGlobalMessageWatch`: لم تعد تمنع إعادة البناء بعد موت القناة (كان الحارس القديم `if (state.presenceChannel) return` يمنع الإحياء إلى الأبد).

### `js/calls.js`
- إضافة `isIncomingCallChannelAlive()` لتجنّب إعادة بناء قناة الإشارات الواردة بلا سبب.

### `firebase-messaging-sw.js` (أُعيد بناؤه)
- نقرة الإشعار: معالج بمرحلة `capture` + `stopImmediatePropagation()`.
- هوية الحدث `identityKey` للمنع من التكرار، مع تسلسل داخلي للعرض (`enqueueDisplay`).
- `normalizePayload` يفك `FCM_MSG` في الدفعة وفي بيانات النقرة.
- `handleCallEnded`: فائتة ⇒ إشعار `missed-*` ويُغلق الرنين؛ غير فائتة ⇒ استبدال الرنين بإشعار صامت ثم إغلاقه.
- `SW_BUILD = 2026-10-12.1`.

### `supabase/functions/send-push/index.ts`
- `buildTag`: tag مستقل للمكالمة الفائتة، وtag فريد للاختبار/المسبار.
- `buildAppLink` + `webpush.fcm_options.link` عند ضبط `APP_PUBLIC_URL` (رابط احتياطي للنقرة).
- تصحيح التعليق الذي كان يدّعي أن الرابط يُتجنّب لمنع الـ SDK من معالجة النقرة — الواقع أن الـ SDK **يبتلع** النقرة بلا رابط، وهذا هو سبب المشكلة.

### `sql/migrations/2026-10-12_v2_5_realtime_replica_identity.sql` (جديد)
- نشر `messages, typing_status, message_reactions, conversations, profiles, call_rooms` في `supabase_realtime`.
- `REPLICA IDENTITY FULL` للجداول التي تحتاج قيم الصف القديم (الفلاتر والحذف).
- فهارس تخدم فلاتر Realtime.
- دالة `realtime_publication_health()` للتشخيص.

### `sw.js`
- رفع `CACHE_NAME` إلى `wa-clone-shell-v14` ليلتقط المتصفح الملفات المعدّلة.

## 2-ب) التحديث النهائي v2.6 (2026-10-13): تعدد الأجهزة + قائمة فورية + بلا رسائل تلقائية

### `sql/migrations/2026-10-13_v2_6_multidevice_no_automated_messages.sql` (جديد)
- حذف مُشغِّلات ودوال الترحيب وبوت الكلمات المفتاحية (`on_message_first_welcome`، `on_message_keyword_autoreply`).
- دالة `register_fcm_token(p_token, p_platform)` بصلاحية `SECURITY DEFINER`: تسجّل توكن الجهاز للمستخدم الحالي وتنقله إن كان مسجّلاً لحساب سابق على الجهاز نفسه (كان upsert العادي يفشل بصمت بسبب RLS).
- `sql/schema.sql` لم يعد يُنشئ الترحيب أو البوت (للتثبيت النظيف).

### `js/push.js`
- تسجيل التوكن عبر `register_fcm_token` مع توافق رجعي: إن لم تُطبَّق الهجرة بعد يُستخدم upsert القديم.

### `js/app.js`
- زر تسجيل الخروج يحذف توكن **هذا الجهاز** قبل `signOut` (وما زالت الجلسة سارية) فلا تصل إشعارات الحساب إلى جهاز خرج منه.
- قائمة المحادثات تتحدّث فورياً من أحداث Realtime دون إعادة تحميل:
  - تحديث `conversations` يحمل المعاينة ووقت آخر رسالة (يكتبهما trigger قاعدة البيانات) → يُطبَّق مباشرة على الصف.
  - رسالة جديدة → تحديث المعاينة والعدّاد وإعادة وضع الصف حسب الوقت (`placeRowByTime`) دون رسم القائمة كلها.
  - رسالة من جهاز آخر لنفس الحساب → تحديث المعاينة فقط (بلا عدّاد).
  - `markRealtimeMessageSeen`: كل رسالة تُعدّ مرة واحدة فقط (لا عدّ مزدوج عند وصولها عبر قناتين).
- `loadContacts`: إن وصل طلب أثناء جلب قائم يُعاد الجلب بعد انتهائه بدل تجاهله (كان هذا يسبب تأخّر أو فقدان تحديث).

### `js/calls.js`
- `CALL_CHAT_CARDS_ENABLED = false`: لا تُنشأ بطاقات مكالمات تلقائية داخل المحادثة. سجل المكالمات (`call_logs`) يعمل كالمعتاد. لإعادة البطاقات غيّر القيمة إلى `true`.

### `supabase/functions/send-push/index.ts`
- إرسال إلى **كل** توكنات الحساب (صف لكل جهاز) عبر `sendToAllDevices` في كل المسارات: رسالة، مكالمة واردة/منتهية، اختبار، مسبار.
- حذف التوكن **فقط** عند خطأ ميّت فعلاً (`404` / `UNREGISTERED` / `registration-token-not-registered` / توكن غير صالح بنيوياً). كان المسار القديم يحذف عند أي `INVALID_ARGUMENT`، وهذا كان يُسقط توكنات أجهزة سليمة بسبب خطأ في الحمولة.
- إعادة محاولة (حتى 3 محاولات مع تراجع زمني) للأخطاء العابرة `429/5xx` والشبكة، وتوازٍ محدود (10).

### `sw.js`
- `CACHE_NAME` = `wa-clone-shell-v14`.

### خطوات النشر الإضافية
1. شغّل `sql/migrations/2026-10-13_v2_6_multidevice_no_automated_messages.sql` في Supabase SQL Editor.
2. أعد نشر الدالة: `supabase functions deploy send-push`.

## 3) خطوات النشر (بالترتيب)

1. **شغّل الترحيل** في Supabase SQL Editor: `sql/migrations/2026-10-12_v2_5_realtime_replica_identity.sql` (آمن لإعادة التنفيذ).
2. **تحقّق من النشر**:
   ```sql
   select * from public.realtime_publication_health();
   ```
   كل الصفوف يجب أن تكون `published = true` و`replica_identity = full`.
3. **اضبط السر الاختياري** للرابط الاحتياطي للنقرة:
   `supabase secrets set APP_PUBLIC_URL=https://<your-app-domain>`
4. **أعد نشر الدالة**: `supabase functions deploy send-push`.
5. **انشر الواجهة** (الملفات الثابتة). بسبب `CACHE_NAME` الجديد سيُحدَّث الـ Service Worker تلقائياً.
6. **على الجهاز**: أغلق التطبيق تماماً وأعد فتحه مرة واحدة حتى يُفعَّل `firebase-messaging-sw.js` الجديد (`SW_BUILD = 2026-10-12.1`).

## 4) التحقق

```bash
npm test          # كل الاختبارات (تشمل automated-off للتحديث v2.6): smoke + flow + ticks + realtime-resilience + push-sw
npm run lint      # 0 أخطاء
```

- `tests/realtime-resilience.mjs` يحاكي سلوك Supabase (إزالة القناة تُطلق `CLOSED`، والاشتراك بجدول منشور يفشل بشكل دائم). على الكود القديم يفشل فحص الـ Singleton (قناتان حيّتان بنفس الـ topic).
- `tests/push-sw.mjs` يحمّل `firebase-messaging-sw.js` الحقيقي داخل sandbox مع محاكاة لسلوك SDK الموثّق في مصدره. على الكود القديم تفشل 6 فحوصات (النقر، الدفعات data-only، tag المكالمة الفائتة، إنهاء المكالمة).

**اختبار يدوي على جهاز حقيقي** (الإشعارات لا يمكن اختبارها كاملةً في بيئة آلية):
1. افتح التطبيق، فعّل الإشعارات، ثم اضغط «إرسال إشعار تجريبي» من الإعدادات.
2. أغلق التطبيق (أو اجعله في الخلفية) وأرسل رسالة من حساب آخر ⇒ يجب أن يظهر إشعار.
3. أرسل رسالتين متتاليتين في نفس المحادثة ⇒ يجب أن يظهر الإشعاران (أو الأحدث بنفس المجموعة).
4. انقر الإشعار ⇒ تُفتح المحادثة الصحيحة وتتمرّر إلى الرسالة.
5. في Console: يجب ألّا تتكرر `CHANNEL_ERROR`/`CLOSED` بشكل متواصل. الرسالة `[realtime] أُعيد بناء (...)` تظهر فقط عند الحاجة.

## 5) ملاحظات وقيود معروفة (لم تُغيَّر عمداً)

1. **تسريب محتمل لحذف الرسائل**: مع `REPLICA IDENTITY FULL` على `messages`، تُبَثّ حمولة الرسالة المحذوفة كاملة لكل مشترك في الجدول، لأن Realtime لا يطبّق RLS على أحداث `DELETE`. الحل الجذري: بثّ الحذف عبر قناة Broadcast خاصة بالمحادثة من trigger. هذا تغيير معماري يحتاج قراراً منك.
2. **قناة الحضور `presence:global` عامة**: أي مستخدم بمفتاح anon يمكنه الانضمام إليها ورؤية معرّفات المتصلين. لا تحمل بيانات حساسة، لكنها تُكشف.
3. **iOS**: إشعارات Web Push على iPhone تعمل فقط للتطبيق المُثبَّت على الشاشة الرئيسية (iOS 16.4+) ومع إذن المستخدم. هذا قيد من النظام، لا من الكود.
4. **الرسائل والتطبيق في المقدمة**: عندما تكون نافذة ظاهرة، يُسلّم الـ SDK الرسالة للصفحة ولا يعرض إشعاراً؛ العرض يتم من `listenForForegroundMessages`. هذا سلوك SDK موثّق في مصدره.
5. **`onTokenRefresh` معطّل** في `push.js` (لا يوجد في Web SDK v9+ الـ modular). التوكن يُزامَن عند كل دخول ودورياً (30 دقيقة) وعند `PUSH_RESUBSCRIBE`. لم يُغيَّر هذا.
